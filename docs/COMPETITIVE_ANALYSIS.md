# NetCanvas — competitive analysis (Nov 2026)

Scope: diagramming + documentation features only (no simulation / CLI emulation). Compared against Cisco Packet Tracer (PT) and Cisco Modeling Labs (CML), draw.io, Visio, Lucidchart (+Lucidscale), NetBox (+topology-views / Visual Explorer) and SolarWinds Network Topology Mapper (NTM); cross-checked with netTerrain, EdrawMax, Zenmap, GNS3 and three OSS editors (Isoflow, networkmaps, esnet/react-network-diagrams).

Legend: ✔ has it · ◐ partial / manual · ✖ no · – n/a or not verified.

Take-away: NetCanvas already beats the general-purpose tools on networking semantics (ports, media, VLAN registry, device editor) and matches them on canvas basics. The gaps cluster in three places: **link rendering quality** (routing, jumps, bundling), **structure** (layers, containers, drill-down, racks) and **data in/out** (per-interface data, tables, imports, reports, PDF).

## C. Conventions worth adopting

**Icon categories (Cisco topology set and the stencil ecosystem).** Cisco publishes its icons as EPS/JPG, Visio .vss and PPT, in PMS 3015 blue or black-and-white, split into *logical* (product) and *conceptual* (presentation) sets, free to use but not to alter. ConceptDraw's packaging of the same set lists 14 libraries / ~450 objects; the recurring families are: Routers (router, broadband, wireless router, route/switch processor); Switches & Hubs (workgroup, multilayer, ATM/ISDN switch, bridge, hub); Security (firewall, IPS, VPN concentrator, lock/key/guard/vault); Wireless (AP, bridge, antenna, WLC); Voice/Collaboration (CallManager, voice gateway, PBX, IP phone); Servers & Storage; WAN/Optical/Carrier (DSLAM, CSU/DSU, modem, satellite, radio tower, carrier routing system); Buildings & Sites (HQ, branch, home office, government); Endpoints & People (PC, workstation, laptop, host, man/woman, car/truck); Media & Clouds (clouds in several colours; line tags for coax/fibre/twisted pair; topology glyphs bus/star/ring/Ethernet). Proposed NetCanvas taxonomy: Routing · Switching · Security · Wireless · Compute & Storage · Endpoints · OT/Industrial (PLC, HMI, drives, IO-Link, robots, vision, sensors) · Sites & Buildings · WAN/Cloud/Carrier · Power (UPS, PDU) · Passive (patch panel, media converter, splitter).

**Interface naming (Cisco).** `Type Slot/Port` or, on stackable Catalyst, `Type Stack/Module/Port` (Gi1/0/1: member 1, module 0 built-in ports, module 1 uplinks); routers start at 0 (Gi0/0), switches at 1; Nexus uses `Ethernet1/1` and `Ethernet1/2/1` for breakouts. Abbreviations: Fa (100M), Gi (1G), Tw (2.5G), Fi (5G), Te (10G), Twe (25G), Fo (40G), Hu (100G); plus `PoN` port-channels, `VlanN` SVIs, `Mgmt0`/`Gi0/0` OOB. For NetCanvas: port-name templates per DeviceDef (`Gi1/0/{n}`), auto-numbering, a regex validator, and abbreviated names on link ends.

**Link labelling.** Minimum: interface at each end + subnet (e.g. `Gi0/1 (10.1.1.0/30) OSPF Area 0`); add VLAN/trunk allowed list, bandwidth and protocol as needed. PT offers port labels *always / on hover*, CML a lab-wide *Show Link Labels* and *Link Bundling* toggle — expose the same three preferences. Network libraries draw bidirectional links without arrowheads; solid = wired, dashed = Wi-Fi/backup, dotted = logical/VPN tunnel. Colour by *function* (red OOB management, blue production, green backup/failover, yellow DMZ/public, grey deprecated/planned-removal) rather than by media; keep media as a line-tag glyph or legend entry.

**Rack diagrams.** 19" (also 10"/21"/23") cabinets; U numbered from the bottom (1 at bottom) with a descending option; equipment heights in whole or half U; full-depth gear blocks the opposite face; 0U gear (vertical PDUs) consumes no U; front and rear elevations; device labels to the right of the rack; shape data per device: asset tag, serial, location/position, manufacturer, part number; include patch panels with front↔rear port mapping; devicetype-library YAML is a ready-made catalogue of u_height/ports per model.

**Document hygiene.** Separate physical (L1/L2) and logical (L3) drawings; show core/distribution/access (or IT/DMZ/OT cell) as horizontal bands or zones; one legend for colours *and* abbreviations; a header/title block with title, version, date, author and classification; keep diagrams in version control and dated for audits.
